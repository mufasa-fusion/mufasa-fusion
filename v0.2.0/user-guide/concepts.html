Concepts#

MuFASA represents each sensor fusion system as a directed, acyclic graph – the Fusion Graph. Its internal nodes define processing operations. Edges encode information flow. Input and output nodes define the boundary of a Fusion Graph, while at the same time functioning as connectors to external data sources or sinks respectively.

The Fusion Graph#

A Graph object represents a Fusion Graph, binding all nodes reachable from its inputs to outputs together. It is responsible for type compatibility checking and orchestrates the execution of the fusion system via its run() method. It also distributes global configuration – crs, bounding box and map raster resolution – to every node.


from mufasa.graph import Graph, BoundingBox

graph = Graph(
    inputs=[...],
    outputs=[...],
    crs="...crs...",
    bbox=BoundingBox(...),
    resolution=(5, 5),
)

graph.run()

Geospatial Detections#

All information flowing within a Fusion Graph is of one of two fundamental data types, Location and Map, or any more specific one derived from them. They all represent geo-referenced detections, optionally with a timestamp and additional metadata.

Every edge adheres to a single data type that is determined by the nodes it connects. Each Node specifies the set of types it accepts via its _input_types and the single one it produces via its _output_type. Only compatible nodes can be wired together.

IO Boundary Layer#

Input and output nodes form the boundary of a Fusion Graph and at the same time bridges to external systems. Within a graph, InputNodes accept no input and OutputNodes produce nothing. They do, however, ingest data from and distribute results to external systems. Moreover, they are responsible for the conversion from and to other standardized or proprietary data formats.

Processing Nodes#

Processing nodes define individual processing units and their wiring makes up a fusion architecture. Any Node that has one or more input types and an output type specified is considered a processing node.
